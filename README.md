## What is deliberately NOT tracked

| Excluded | Why |
|---|---|
| WordPress core | managed by WP updates |
| `wp-content/plugins/*` (356 MB) | Elementor/Pro, WooCommerce, ACF, Stripe, PayPal, Breeze etc. — third-party and commercially licensed; WP's updater owns them |
| `themes/hello-biz`, `themes/hello-elementor` | third-party parent themes |
| `wp-content/uploads/` (248 MB) | media — lives in backups |
| `wp-content/languages/` (17 MB) | generated translation files |
| `wp-config.php` | DB credentials and salts |
| `mu-plugins/automation-by-installatron.php` | host-generated |
| `mu-plugins/elementor-safe-mode.php` | generated by Elementor's safe mode toggle |
| `.duckversions/` | file-manager auto-backups |
| caches, logs, `node_modules` | generated |

Because third-party plugins are not tracked, this repo is **not** a runnable
local site on its own. It is a deployment and history repo for our own code.

### `vendor/` is committed on purpose

`heat-loss-calculator` has a `composer.json`, but Cloudways' git deployment does
not run `composer install`. The 840 KB `vendor/` directory is therefore tracked
so deploys are complete.

## Pulling the server state down

```bash
DRY_RUN=1 ./bin/pull-from-staging.sh   # preview
./bin/pull-from-staging.sh             # apply
```

`--delete` is on, scoped to the four tracked paths.

## Cloudways Git deployment

Set the deployment path to `public_html` so the repo's `wp-content/...` paths
land correctly.

> **Verify before the first real deploy:** confirm on staging whether
> Cloudways' git deployment *removes* files in the deployment path that are
> absent from the repo. If it does, `wp-content/uploads` and the untracked
> plugins would be at risk, and the deployment path must be narrowed instead.
